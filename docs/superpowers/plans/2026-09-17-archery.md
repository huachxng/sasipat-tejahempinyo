## 1. Frontmatter: fields and grammar

### 1.1 Fields (all flat, all optional)

| Field | Type (Obsidian `types.json`) | Zod | Why needed / not derivable |
|---|---|---|---|
| `scores` | `multitext` | list of strings, default `[]`; items preprocessed with `String()` so a bare `- 560` (YAML number) does not fail the build | Per-round numbers; nothing else holds them |
| `placing` | `number` | blank → absent; integer 1–3; error message below | `result` is free prose using Thai "1st runner-up = 2nd" conventions, and Navy has two placings in one sentence; parsing it is fragile and an off-by-one would be visible. Explicit integer = the best placing at that event |
| `division` | `text` | trimmed string | Appears inside `result`/`title` only as prose; needed as a clean chip ("U15 Women") |
| `distance` | `text` | trimmed string | Event-level fallback for placing-only entries (Ratchaburi 18 m) and for the record panel; per-round distance inside a score string wins when present |
| `bow` | — | **not added** | Every entry is recurve for the foreseeable future; it would be a field that always says the same thing. Add later without migration if compound/barebow ever appears |

Zod messages (author-facing, same style as `category`):
- `placing`: `placing must be a whole number from 1 to 3 (1 = winner). Leave it out for anything below the podium`
- `scores` item that is not text (after `String()` coercion this can only be `null` from a blank list item): `each scores line must be text like "Ranking round | 560/720 | 72 arrows | 70 m"`

Unparseable-but-textual score strings are deliberately **not** zod errors (zod errors fail the build); they are check-content warnings (§5).

Add a small helper in `src/schemas/common.ts` — `emptyAsAbsent(schema)` — generalising the preprocess already inside `optionalDate`, and use it for `placing`.

### 1.2 Grammar of one `scores` item

```
<label> | <score> | <detail> | <detail> …
```
- Segments are split on `|`, whitespace-collapsed, blanks dropped (exactly like `parseLink`).
- **label**: first segment, free text, unless the first segment is itself a score, in which case the label defaults to `Score` (or `Match` for a match score).
- **score** (exactly one required somewhere; first wins): 
  - `560/720` or `560 of 720` (total/max, optional `pts`/`points`)
  - `560` (total only; optional `pts`/`points`)
  - `6-4`, `6–4`, `6:4`, `6-4 sets` (match set score; normalised to `6–4` with an en dash)
- **details** (any order, each recognised by pattern, first wins per field):
  - `72 arrows` / `72 arrow` → `arrows`
  - `70 m` / `70m` / `70 metres` / `18 meters` → `distance` normalised to `"70 m"`
  - anything else (e.g. `vs seed 3`, `indoor`, `shoot-off 9–8`) → `note` (joined with ` · `)
- Derivations (helpers, not stored): `max = explicit max ?? arrows × 10`; `avg = total ÷ arrows` (only when both are explicit); arrows are **never** derived from max (an author who wants the target face must give the arrow count — one README sentence says so).

### 1.3 Six examples (including edge cases)

1. `Ranking round | 560/720 | 72 arrows | 70 m` → `{label:'Ranking round', total:560, max:720, arrows:72, distance:'70 m'}`; avg 7.78 → target face.
2. `Ranking round | 560 | 72 arrows` → total 560, arrows 72, max derived 720; target face.
3. `Elimination | 6-4 | vs seed 3` → `{label:'Elimination', matchScore:'6–4', note:'vs seed 3'}`; readout only, no target.
4. `Qualification | 18 m | 540/600 | 60 arrows` (segments out of order, indoor) → same shape as #1 with distance `18 m`, avg 9.0.
5. `Ranking round | 560` → total only; readout "560"; no target (no arrows), no average.
6. `560/720` (no label) → label `Score`, total/max parsed. And the garbage cases that must return `null`: `personal best`, `Elimination | reached quarter-finals`, ` | | `, `''`, `Ranking | 560/720/800` (three-part fraction is not a fraction and not an integer → no score → null), `6-4-2`.

## 2. `src/lib/archery.ts` — parser and helpers (plain TS, no `astro:*`)

Exports (shape, not code):
- `interface ParsedScore { label: string; total?: number; max?: number; arrows?: number; distance?: string; matchScore?: string; note?: string; raw: string }`
- `parseScore(raw: string): ParsedScore | null` — algorithm exactly as §1.2; returns `null` when no score segment (total or match) is found. Never throws; accepts any string.
- `maxOf(s)`, `averagePerArrow(s): number | undefined`.
- `bestScore(raws: string[]): ParsedScore | undefined` — highest `averagePerArrow` wins; ties → first; else the first with a `total`; else undefined.
- `formatScore(s): string` — mono readout: `560 / 720 · 72 arrows · 70 m · avg 7.8` (omit parts that are unknown; match scores render `Elimination 6–4 · vs seed 3`). `avg` is `toFixed(1)`.
- `formatScoreForResume(s): string` — `560/720, 72 arrows, 70 m`.
- `ordinal(n): string` — `1st 2nd 3rd`.
- `ringFor(avg): number` — `clamp(round(avg), 1, 10)`; and `radiusFor(avg)` = `(10.5 − avg) × 10` on a 100-unit face (an average of exactly 8.0 sits in the middle of the 8 ring; 7.78 → r 27.2, still inside ring 8 whose band is r 20–30). This is the one visual mapping decision; document it in the file header.
- `archeryPresentation(data: { category, scores, placing?, division?, distance?, result? })` → discriminated union `{ kind: 'target', score, avg, ring, placing?, division?, distance }` | `{ kind: 'compact', placing, division?, distance? }` | `{ kind: 'none' }`. Rules: not `athletics` → none; a parsed score with total **and** arrows → target (best one); else `placing` present → compact; else none. `distance` for the target = the score's distance ?? top-level `distance`. This single function is what the component, the record panel, the resume and the tests all use, so the "WAYC shows nothing" rule lives in one place.
- `shortTitle(title)` — text before the first ` — ` (all six archery titles use it), for the record panel list.

Score-string problems for check-content (§5) come from a second helper `scoreProblems(raw): string[]` (e.g. total > max, total > arrows × 10) so the wording is tested in one place.

## 11. Risks and mitigations
